Key decisions — Make the next tool easier.
Soham Sane / Cognition take-home

I built a refunds queue, changed it in a fresh Devin session, then reused it for merchant reviews. The real test was whether the second task became easier.

The change workflow
Describe a task → Use a Playbook → Devin builds → Review & merge
Plain-language request → Repeatable instructions → Code + checks → Human approval

The app we built
Refunds review: approve, reject, find overdue requests.
Merchant review: same foundation, separate records.
Both share an interface, decision rules and history.
React interface / Python service / SQLite database.

Why I chose this scope

Start with one real workflow.
Refunds exercise search, decisions and history in one small app. I saved the overdue filter for a later session to test maintenance as well as creation.

Reuse the foundation.
Merchant reviews reuse the same screens and rules, with separate records. That avoids maintaining copies, but a shared change can affect both tools.

Keep a person in the loop.
Playbooks guide Create, Update, Variant and Health tasks. The update needed a publishing handoff, and automatic triggers were not conclusively proven.

A useful prototype. Still a production gap.
Synthetic data and selectable demo roles kept the build small. Real sign-in, protected audit records, reliable hosting and backups still need engineering. The later Devin security profile is configured, but untested; it does not secure the app itself.

My next step: keep Power Apps and pilot one low-risk, read-only tool before deciding whether the ongoing ownership cost is worth it.
