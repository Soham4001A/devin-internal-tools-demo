Key Decisions — Devin for internal tools
Soham Sane / Cognition take-home

A practical evaluation of building, changing and reusing internal tools, with refunds, merchant reviews and settlement integration as working examples.

Your workflow → Reusable brief → Devin session → Human review

01 What is Devin?
• An AI software engineer that edits code, runs checks and uses a browser in a cloud environment.
• Requests and feedback can be conversational; the result is reviewable code your team owns.
• It reduces implementation effort. Engineering still owns correctness and operation.

02 Refunds Review: the first build
• A queue to search requests, approve or reject with a reason, and inspect decision history.
• A fresh session added an overdue filter. Merchant Reviews reused the base with separate records.
• Shared screens and rules avoid copied apps, but changes need regression checks. Data and personas are fictional.

03 Customize around your workflow
• Connect GitHub and provide project instructions so Devin follows your build and review process.
• Keep data in AWS or your existing database. Configure APIs, tools, credentials and network access; cloud access can use temporary OIDC credentials.
• Jira can hand off work and receive results. Connected Teams users can ask questions and give feedback in conversation.
• Ask for a browser video, review the behavior, then request a change. Jira, Teams and AWS are documented capabilities, not connections tested here.

04 Playbooks: repeatable instructions
• Create, Update, Variant and Health capture recurring tasks and what “done” means.
• Repository instructions carry setup and checks between sessions. Playbooks guide work; they do not enforce permissions.

05 Settlement: own the connection
• A separate follow-up calls a mock risk vendor with server-held OAuth client credentials.
• Power Apps custom connectors do not support that grant directly. An intermediary is possible; our backend provides control and adds maintenance.
• The app enforces roles and tenant boundaries on the server. Those controls are also possible in Power Platform.

06 Automations and session controls
• Events or schedules can launch work. Our configuration filters requesters and limits session access and usage.
• Tags organize sessions; app roles, Devin access and release permissions are separate controls.
• Runs used manual intervention. Trigger filtering and profile enforcement still need conclusive tests.

07 Limits compared with Power Apps
• Managed data, identity, governance and release tooling are part of the platform’s value.
• Custom apps need hosting, backups, security and support. Fast creation alone does not prove a saving.

Our recommendation: keep Power Apps; pilot the next tool.
Run a 30-day pilot on one new, low-risk tool with a named owner. Measure review and support time, validate production controls, and compare ownership cost with the license spend you can actually remove.

Devin built the apps; Codex assisted orchestration, review, fixes and presentation. Synthetic data throughout. Settlement follow-up timed separately. Local checks and browser journeys passed.
